## 一次轻点，一段属于自己的记录

开始之前，选好单人或双人模式。轻点手表，时长开始流动，运动次数、节奏和心率在同一屏幕里安静更新。落腕、熄屏，不必为了保住记录而一直盯着屏幕。需要歇一会儿，就按暂停；结束时，一次保存。

回到手机，过程变成可以慢慢看的曲线：哪一段节奏更均匀，哪一段心率逐渐升高，什么时候动得多，什么时候停了下来。你可以留下记录，也可以把数据导出，按自己的方式理解它。

**隐记是一款面向私人亲密活动场景的个人运动记录原型。** 它记录佩戴者的手腕运动与心率，不判断行为类型，不检测高潮，也不把数字当作表现评分。

> **当前版本约定**
>
> - 默认 **Y 轴计数**；X/Z 可选，三轴自动仍为实验功能，真机反馈存在漏计。
> - 默认 **不把训练写入苹果健康**；在 iPhone 的单条记录里手动选择同步。
> - 双人模式 **只记录佩戴者**，不采集另一人的心率，也不连接另一块手表。
> - 核心流程已实现并通过构建和合成测试，计数准确率与长时间稳定性仍需真机校准。

## 手腕上的一屏，手机里的一段故事

| Apple Watch：专注当下 | iPhone：看见过程 |
| --- | --- |
| 单人 / 双人并列选择 | 按全部、单人、双人筛选 |
| 一屏显示次数、时长、节奏、心率 | 每次记录的完整详情 |

## 不止一个总数

### 把节奏放到时间里

手机详情用相同的有效记录时间轴展示心率、节奏和运动强度。手动暂停不计入有效时长，暂停与明显传感器断流分段显示。心率不可用时留空，不用零值或虚构数据填补。

心率曲线使用最近 30 秒内的可用读数，节奏与强度按秒汇总。长记录会逐步抽稀曲线，控制手表内存；汇总指标仍使用全部有效观测。

### 区分运动、静止和没有测到

- **运动时长**：每秒窗口的三轴去重力加速度 RMS 达到暂定阈值 0.08 g。
- **静止时长**：有传感器数据，但低于阈值。
- **未观测时长**：启动等待或采样断流等未覆盖时间。

静止只是一项统计，**不会自动暂停或结束记录**。阈值是需要校准的原型参数，不代表已经验证的行为分类。

### 强度与稳定性，各有自己的含义

平均强度是按观测时间加权的加速度 RMS；最高强度是瞬时三轴幅值峰值。单位为 **g**，不能换算成力量、距离或身体位移。

节奏稳定性根据连续动作间隔的波动计算，至少有 4 个有效间隔才显示。数值越高，代表间隔越均匀，不代表更健康或表现更好。

## 计数：先可靠，再探索

默认 Y 轴使用本地集成的 **RepMotion** 检测运动峰值，提供三档灵敏度。开始与恢复后预热约 3 秒，实际计数受佩戴位置、动作方向和活动方式影响。

实验性三轴算法使用主成分分析（PCA）估计主要运动方向，再以带符号投影和双阈值识别完整往复周期。它不会把三轴计数简单相加，也不直接对加速度模长计峰，避免重复与倍频问题。

目前三轴版本对快速转腕、近圆周运动、低幅度或超出周期范围的动作可能漏计。因此默认已恢复 Y 轴，三轴保留用于对照实验。**不要把通过合成测试理解为已证明真实准确率。**

建议首次使用时人工数一小段动作，对照结果后再调整检测轴与灵敏度。历史记录保留所用检测方式，便于比较。

## 苹果健康，由你决定哪一条留下

手表使用 HealthKit 运动会话支持后台运行与心率采集，结束时不自动保存训练到健康。

需要同步时：

1. 在 iPhone 打开某条记录。
2. 点击 **同步到苹果健康**。
3. 首次使用按系统提示授权。
4. 查看同步结果。

训练按“其他”类型保存，并保留开始、结束与暂停信息。次数、节奏、模式等写入自定义附加数据，**苹果自带页面不保证显示这些字段**。同步时会尝试关联手机健康中同一时间段的真实心率样本；样本缺失或未授权时不会伪造。

已保存的训练不会因为删除 App 内记录而自动删除，需要在健康 App 中单独管理。系统自身的心率采样和活动圆环更新，也不等同于本 App 主动保存训练。

## 数据在哪里

不需要注册账号，不依赖自建服务器。应用代码通过 Apple 的设备连接框架同步两端，通过 HealthKit 处理用户主动选择的健康写入；没有向自建分析服务器上传记录的逻辑。设备备份和系统云同步仍受用户的系统设置控制。

| 文件 / 数据 | 内容 |
| --- | --- |
| `Documents/sessions.json` | 记录摘要、模式、分析结果与过程点 |
| `motion-UUID.csv` | 可选原始运动采样：时间戳、三轴加速度与角速度 |
| 摘要 CSV | 时间、次数、节奏、心率摘要、强度、模式和检测方式等 |
| 过程曲线 CSV | 有效记录秒数、连续段、节奏、心率与强度 |

原始采样时间戳是设备单调时钟秒数；摘要开始时间使用 ISO 8601。加速度单位 g，角速度单位 rad/s。原始运动 CSV 不包含心率序列，心率过程数据通过单独的曲线 CSV 导出。

手机保留独立副本，手表删除记录不会联动删除手机历史。CSV 是明文文件，分享时由你决定接收者。旧记录缺少的新指标显示为空，不从旧摘要补造曲线。演示记录明确标记，不纳入趋势或健康写入。

## 在自己的设备上运行

### 环境

- Apple Watch：watchOS 10 或以上
- iPhone：iOS 17 或以上
- 已用于构建验证：Xcode 27、iOS / watchOS Simulator 27
- 一台 Mac、已与 iPhone 配对的 Apple Watch，以及自己的 Apple 开发签名配置

### 安装

1. 用 Xcode 打开 `PulseWatch.xcodeproj`。
2. 在 `PulsePhone` 和 `PulseWatch` 的 **Signing & Capabilities** 中选择自己的 Team；项目携带原开发环境的 Team 标识，克隆后需改成自己的配置。
3. 如果更改 Bundle Identifier，同时调整手机 ID、手表 ID 和 `App/Info.plist` 中的 `WKCompanionAppBundleIdentifier`，确保配套关系一致。
4. 选择 **PulsePhone → 自己的 iPhone → Run**，安装手机端。
5. 选择 **PulseWatch → 自己的 Apple Watch → Run**，安装手表端。
6. 两端各打开一次，按提示授权运动与心率相关权限。

更新时请保留原 Bundle Identifier，以便覆盖安装并保留历史；默认计数和健康写入行为变更需要两端都更新。

模拟器没有真实手腕运动与心率。可在手表设置开启演示模式检查前台流程；不要用模拟器结果判断真机采样或后台连接质量。

App/
├── ContentView.swift          # 手表一屏界面、历史与设置

技术栈：**SwiftUI** 构建两端界面，**Core Motion** 获取运动数据，**HealthKit** 支持运动会话与心率，**WatchConnectivity** 传输记录，**Swift Charts** 展示趋势。RepMotion 已随源码固定保存，无需联网拉取远程 Swift 包。

```sh
# 手机与配套手表的模拟器联合构建
xcodebuild -project PulseWatch.xcodeproj \
  -scheme PulsePhone \
  -destination 'generic/platform=iOS Simulator' \
  -configuration Debug -derivedDataPath build \
  CODE_SIGNING_ALLOWED=NO build

# 核心算法与存储测试
swift test
```

当前已有 **21 项自动化测试**，覆盖周期检测、方向变化、噪声与转腕、断流恢复、运动/静止分类、稳定性、长记录内存约束、旧数据兼容、乱序合并及 CSV 导出。手机和手表模拟器构建通过，手机端曾完成模拟器安装与启动检查。

仍需要真机验证：实际动作准确率、心率权限与采样、后台持续运行、两端同步及健康手动导入。系统终止、关机、传感器异常或另一项训练抢占都可能中断记录；本项目不是全天候或医疗级监测工具。
